# 方法论

`ruststream-amqp` 如何测量自己：三个循环、在真实 Broker 上的运行、受 Broker 限制的判定计算，以及代码计数。流程就是框架自己的流程（[RustStream 方法论](https://powersemmi.github.io/ruststream/latest/benchmarks/#methodology)），本页说明它在 AMQP 1.0 上是什么样子。

## 三个循环 {/* #the-three-loops */}

一个进程把场景跑三遍，作为三个循环，它们只有一处不同：承载消息的是什么。

- **裸客户端。** 一个 `fe2o3-amqp` 接收者，直接驱动：接收、解码、读取一个字段、接受投递。
- **Broker crate。** 本 crate，上面什么也没有：Broker 建立连接，[地址描述符](api:ruststream_amqp::AmqpAddress)打开一个订阅，一个循环从它的流中取出投递、解码并 ack。
- **RustStream。** 用户写的服务：一个 `#[subscriber]` 处理器及其外围的应用。

其余一切在三个循环中都相同：连接、每条链路所在的会话、256 的链路信用、投递保证、ack 的位置、解码成同一个结构体、载荷字节、带四个工作线程的 tokio 运行时，以及二进制程序。

消息体是 512 字节的 JSON。它解码成一个包含两个整数字段的结构体，因此解码不做内存分配，数字反映的是本 crate，而不是 JSON 解析器。

## 运行 {/* #the-run */}

- **每次运行使用新的地址。** 一次运行永远看不到之前的运行留下的东西。
- **消费者先附加。** 随后，另一个连接上的生产者向它供给消息，最多提前 8192 条。生产者以预先结算的方式发布，因此运行测量的是消费一侧，而不是 Broker 确认一次发送有多快。
- **在三个循环中，计时窗口都从第一次投递开始，到最后一次投递解码完成时结束。** 建立连接、开启会话和附加链路都在窗口之外。
- **消息条数来自一次探测**，它测量裸循环的速率，因此在任何机器上，测量的运行都至少持续五秒。
- **各循环交替进行**：裸、crate、RustStream，共三轮。每个循环报告它最佳、中位和最差的一轮。

当消费者在运行的大部分时间里都在等 Broker 时，该行标为 `受 Broker 限制`。这是算出来的：一次探测为 20000 次等待 disposition 的发送计时并取中位数，传输说明一次投递需要多少次往返，二者之积达到每条消息测得时间的一半时，该行就被标记。在这里，一次投递不需要往返：Broker 凭客户端在后台补充的信用进行 transfer，接受投递时也不等待应答。往返时间与机器信息一起公布，因此这个计算可以核对。

## 代码计数 {/* #the-code-count */}

[开销图](index.md#cost-of-the-code)的每个场景都是用户写的服务，基于 [`AmqpBroker`](api:ruststream_amqp::AmqpBroker)，连接同一个 Broker，构建时不带 `testing` 特性，运行在单线程运行时上。一个独立的线程在另一个连接上，于各个测量区间之间填充队列，它的每次发布都等待 Broker 接受。

指令数来自 callgrind，内存分配来自 DHAT。一个场景依次在一次投递、1000 次、2000 次上运行。后两次之差是一条消息的稳态开销，单次投递就是冷启动。

套接字是真实的，所以同一个二进制程序每次运行的计数都会略有变动：一次读取带进多少次 transfer，取决于 Broker 当时已经写出了多少。五次运行中，每条消息的指令数相差在千分之二以内。与保存的基线对照时，某个场景的指令数多出百分之二就算失败。内存分配在每次运行中都受每个场景声明的下限约束，下限是见过的最高计数再加千分之一。

## 自己运行 {/* #running-it-yourself */}

```bash
just bench
```

这条命令按 `docker-compose.test.yml` 启动测试环境，运行对照，停止测试环境，并重写 `docs/benchmarks/results.json`。它大约需要一分钟，并且需要独占机器。它会清空 `RUSTFLAGS`，因此二进制程序不会绑定到构建它的 CPU 上。两条命令都按发布版本的方式构建基准测试，跨 crate 启用完整的链接时优化（fat LTO），因此这些数字描述的正是服务实际使用的代码。

```bash
just bench-code
```

代码计数大约需要半分钟，并且需要 valgrind。这条命令会自己安装基准测试运行器，版本是锁文件固定的那个。在 `main` 上运行 `just bench-code --save-baseline=main` 记录基线，在分支上运行 `just bench-code --baseline=main` 与它对照。
