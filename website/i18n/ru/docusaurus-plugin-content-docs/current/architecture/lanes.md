# Партиции воркеров

Одна подписка читает свою очередь через одну принимающую связь и одну задачу приёма, а
`workers(n, by_key)` раскладывает доставки по партициям воркеров по ключу из `group-id`.

<Diagram name="lanes" words={words} />

Брокер отправляет передачи в счёт кредита связи, по умолчанию 256 передач, а клиент выдаёт новый
кредит по мере того, как сервис урегулирует доставки. Задача приёма передаёт каждую доставку в
канал глубиной в кредит, поэтому обработчика ждут не больше доставок, чем умещается в один кредит.
Пока доставка ждёт места в этом канале, задача приёма продолжает выполнять урегулирования. Поэтому
поток, который никто не опрашивает, не задерживает подтверждения уже выданных доставок.

Поток выдаёт по одной доставке. Без `workers` один цикл вызывает обработчик для каждой доставки по
очереди, и порядок очереди сохраняется.

`workers(n, by_key)` запускает `n` партиций воркеров. Доставка попадает в ту партицию воркеров, на
которую указывает хеш её ключа партиционирования, а партиция воркеров выполняет свои доставки по
порядку. Ключ партиционирования хранится в свойстве `group-id` сообщения, поэтому сообщения одной
группы сохраняют порядок, а разные группы выполняются параллельно. У доставки без ключа нет ключа
партиции воркеров, и такие доставки по кругу распределяются по партициям воркеров.

Чтобы выйти за пределы одного процесса, сервис запускает больше реплик на том же адресе `queue`.
Их получатели конкурируют, и каждое сообщение достаётся одному из них. Группы сообщений Artemis
отправляют все сообщения с одним `group-id` одному и тому же получателю, поэтому группа сохраняет
порядок и между репликами. В Azure Service Bus `group-id` - это идентификатор сеанса.

[Обработчик пакетов](api:ruststream_amqp::AmqpAddress::batch_wait) берёт пакет, который клиент
собирает из потока: до размера, заданного в точке монтирования, или меньше, если раньше истекает
`batch_wait` (по умолчанию 10 миллисекунд). Кредит и размер пакета независимы. Кредит ограничивает,
сколько брокер отправляет заранее, а размер - сколько сообщений видит один вызов обработчика.
