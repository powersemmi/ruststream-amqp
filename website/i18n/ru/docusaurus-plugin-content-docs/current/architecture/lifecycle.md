# Жизненный цикл

[`AmqpBroker::new`](api:ruststream_amqp::AmqpBroker::new) записывает конфигурацию, connect
открывает соединение и сеанс издателей, старт присоединяет каждую подписку, а завершение работы
идёт изнутри наружу.

<Diagram name="lifecycle" words={words} />

`new` не выполняет ввода-вывода, поэтому билдер сервиса остаётся синхронным. Рантайм подключает
брокер при старте приложения. Подключение разбирает URL, открывает сокет, проходит
аутентификацию, открывает соединение и начинает сеанс, который делят издатели. Если URL не
разбирается, сокет не открывается или брокер отклоняет вход, старт возвращает ошибку
`AmqpError::Connect`.

Дескриптор каждой подписки разрешается один раз, по подключённому брокеру. Пустой адрес
отклоняется до любого ввода-вывода. Подписка начинает сеанс, присоединяет принимающую связь со
своим кредитом и запускает задачу приёма, которая владеет этой связью. Если брокер отклоняет
присоединение, старт возвращает ошибку `AmqpError::Attach` с именем адреса.

Отправляющую связь присоединяет первая публикация в её адрес, а не старт. Сервис, который только
читает, не присоединяет ни одной.

Завершение работы помечает соединение закрытым и разбирает его изнутри наружу. Каждая задача
приёма отсоединяет свою связь и завершает свой сеанс, затем закрываются отправляющие связи,
завершается сеанс издателей, и последним закрывается соединение. Пока закрывается внутренний слой,
внешний ещё передаёт ему ответы брокера. Каждый шаг выполняется, даже если предыдущий вернул ошибку, и
наружу возвращается самая внутренняя ошибка. Подписка, открытая в момент завершения, выдаёт
доставки, которые держит, и заканчивается. Если урегулировать такую доставку после этого,
урегулирование вернёт ошибку.

Брокер, скопированный до подключения, делит соединение со своей копией. Копия, которую обвязка
тестов подключила внутри процесса, после этого не может подключиться к серверу, и обратный
порядок тоже отклоняется.
