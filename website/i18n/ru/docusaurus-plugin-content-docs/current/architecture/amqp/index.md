# Соединение

AMQP 1.0 соединяет два контейнера одним соединением. Внутри соединения идут сеансы, а внутри
каждого сеанса - связи, которые переносят сообщения в одну сторону.

<Diagram name="connection" words={words} />

Контейнер - это участник протокола: сервис - один контейнер, брокер - другой. Сервис
представляется идентификатором контейнера `ruststream`, если
[`container_id`](api:ruststream_amqp::AmqpBroker::container_id) не задаёт другой. Консоль брокера
показывает соединение сервиса и его связи под этим идентификатором.

Соединение - это один TCP-сокет. На URL `amqps://` оно начинается с TLS. Затем SASL
аутентифицирует сервис механизмом PLAIN, ANONYMOUS или EXTERNAL, и два контейнера обмениваются
кадрами `open`.

Сеанс - это пара каналов внутри соединения. У каждого канала есть окно, которое ограничивает число
передач, идущих по нему одновременно. Крейт начинает один сеанс, общий для всех издателей
соединения, и ещё по одному на каждую подписку. Медленная подписка заполняет своё окно и никогда
не занимает окно издателей или другой подписки.

У связи есть имя, и она переносит сообщения в одном направлении. Отправляющая связь идёт от
сервиса к узлу, а принимающая связь - от узла к сервису. Каждый конец связи - терминус, и терминус
на стороне брокера называет узел его адресом. У связи есть и собственный кредит, который
показывает страница [Передачи](transfers.md).

Стандарт определяет кадры протокола, но не смысл адреса. Будет ли `orders` очередью или темой,
решает брокер, как показывает страница [Адреса](addresses.md).

Эта модель взята из спецификации
([транспорт](http://docs.oasis-open.org/amqp/core/v1.0/os/amqp-core-transport-v1.0-os.html),
[безопасность](http://docs.oasis-open.org/amqp/core/v1.0/os/amqp-core-security-v1.0-os.html)).
